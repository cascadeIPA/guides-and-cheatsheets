# ------------------------------------------------------------------------------
# 1. ENVIRONMENT & CONFIGURATION
# ------------------------------------------------------------------------------
# Verify Go is installed correctly and display the current version.
go version

# Display all active Go environment variables (e.g., GOPATH, GOROOT, GOOS).
go env

# Modify a specific Go environment variable permanently.
# Note: Changes are written to the os.UserConfigDir()/go/env file.
go env -w GOPATH=$HOME/dev/go-workspace

# Reset an environment variable to its system default:
go env -u GOPATH


# ------------------------------------------------------------------------------
# 2. WORKFLOW CORRECTION: THE DEATH OF GOPATH (Go Modules)
# ------------------------------------------------------------------------------
# EXPLANATION:
# In your original notes, you mentioned that building via GOPATH "doesn't work 
# for me" and relied on placing code inside `~/dev/go-workspace/src/...`.
# 
# Since Go 1.11, the legacy `$GOPATH/src` workspace model has been deprecated. 
# The enterprise standard is now "Go Modules". You can place your project folder 
# ANYWHERE on your system. You just need to initialize a module file (go.mod) 
# inside that folder.

# Step 1: Create a project folder anywhere and navigate into it.
mkdir -p ~/projects/my-go-app
cd ~/projects/my-go-app

# Step 2: Initialize the module. 
# The module name is typically the Git repository URL (even if not pushed yet).
go mod init github.com/your-username/my-go-app
# This creates a 'go.mod' file which tracks your dependencies and Go version.


# ------------------------------------------------------------------------------
# 3. RUNNING & BUILDING
# ------------------------------------------------------------------------------
# BUILD AND RUN (Development)
# Compiles and executes a single file directly into memory without leaving a 
# compiled binary on your disk. Ideal for testing.
go run main.go

# Alternatively, run all .go files in the current directory:
go run .

# COMPILE TO BINARY (Production)
# Compiles the code and creates an executable binary file in the current directory.
# If you are in a module directory, just run:
go build

# Compile a specific file and name the output binary explicitly (-o flag):
go build -o my-app main.go

# Execute the compiled binary natively on Linux/Android:
./my-app


# ------------------------------------------------------------------------------
# 4. DEPENDENCY MANAGEMENT
# ------------------------------------------------------------------------------
# Under the modern Go Modules system, 'go get' no longer blindly downloads 
# source code into `$GOPATH/src`. Instead, it registers the dependency in your 
# `go.mod` file and securely downloads the module cache.

# Add a specific dependency to your project:
go get github.com/fatih/color

# Enterprise Standard: Clean up dependencies.
# This command scans your code, adds missing dependencies to go.mod, and 
# removes any unused dependencies. Always run this before pushing to Git.
go mod tidy


# ------------------------------------------------------------------------------
# 5. CROSS-COMPILATION (Bonus)
# ------------------------------------------------------------------------------
# Go makes it incredibly easy to compile binaries for other operating systems 
# and architectures directly from your current machine by temporarily setting 
# the GOOS and GOARCH variables.

# Compile a Windows executable from your Linux/Termux shell:
GOOS=windows GOARCH=amd64 go build -o my-app.exe

# Compile a Linux binary for a standard GCP x86_64 Server:
GOOS=linux GOARCH=amd64 go build -o my-server-app

# Compile a Linux binary specifically for a Raspberry Pi or ARM server:
GOOS=linux GOARCH=arm64 go build -o my-arm-app
